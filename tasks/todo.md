# Довести прод до робочого стану

## Контекст

Аудит (попередній файл, тепер `tasks/archive/2026-08-26-audit.md`) знайшов
дірку в Edge Functions і задокументував решту знахідок. Перевірка проду
показала: **міграції всі 65 застосовані та працюють**, а Edge Functions у проді
досі старі. Плюс під час перевірки знайдено третій випадок того самого класу
помилки — гейт лише по `role = 'admin'`, який виключає `owner`.

## Що робимо

### 1. Овнер не існує для Slack (нова знахідка) ✅

Три місця в Edge Functions фільтрують `.eq("role", "admin")`:

| Місце | Наслідок |
|---|---|
| `slack-notify:288` | вибір адмінів, кому надіслати DM про нову заявку → у воркспейсі, де єдиний адмін це власник (а це стандарт після founder-flow), повертається `no_admins` і **ніхто не отримує нічого** |
| `slack-notify:668` | Home Tab адмінів не оновлюється після рішення |
| `slack-oauth:106` | fallback admin-approval flow не може ідентифікувати інсталятора-власника → `no_matching_admin_profile` |

БД чиста: перевірено `pg_policies` і `pg_get_functiondef` у проді — жодного
гейта з `'admin'` без `'owner'`. Проблема лише у функціях.

- [x] `.eq("role","admin")` → `.in("role", ["admin","owner"])` у трьох місцях
- [x] Регресійний тест на весь клас: жодна функція в `supabase/functions/` не
      має права фільтрувати по `role` = лише `admin`. Побачити ЧЕРВОНИМ
