### Знайдено дірку в безпеці

Міграція `20260825170000` додала `status = 'active'` в `is_workspace_admin()`, і
тест підтвердив, що деактивований адмін втрачає права в RPC. Але
`invite-employee` і `delete-employee` перевіряли **лише роль**. Деактивований
адмін зберігає auth-користувача (на відміну від м'якого видалення, яке його
прибирає), тож може отримати JWT через OTP і працювати в обхід інтерфейсу.

Доведено мутацією:

| Функція | Без перевірки | З перевіркою |
|---|---|---|
| `invite-employee` | `200` — працівника **справді запрошено** | `403` |
| `delete-employee` | пройшов бар'єр, упав на `500` посередині | `403`, жертва лишилась активною |

Виправлено в обох; додано тести `EF-7` і `EF-7b`. Шаблон у скілі
`new-edge-function` теж виправлено.

> **Не задеплоєно.** `supabase db push` не деплоїть функції. У продакшені дірка
> лишається відкритою, поки не виконано `supabase functions deploy invite-employee`
> і `delete-employee`.

### Шість тестів, які не могли впасти

| Тест | Чому був порожній |
|---|---|
| «адмін погоджує заявку» | кнопки лише з іконкою, без `aria-label` → `getByRole(name)` не знаходив нічого, `.first().count()` = 0, тіло під `if` не виконувалось |
| «адмін відхиляє заявку з причиною» | те саме; плюс причину ніколи не перевіряв |
| «пошук фільтрує список» | `page.locator("tbody tr")` на сторінці з `div` → `expect(count).toBe(0)` правдиве до і після фільтрації |

| «Danger zone» ×2 | `if (count === 0) return` — «UI ще не готовий», хоча UI давно є |

### TypeScript 7 — спробувано, відкочено

| Перевірка під TS 7.0.2 | Результат |
|---|---|
| `npm run typecheck` | ✅ чисто |
| `npm run build` | ✅ ок |
| `npm test` | ✅ 393 / 393 |

Єдиний блокер — `typescript-eslint`. Найновіший стабільний 8.68.0 має peer
`typescript >=4.8.4 <6.1.0`; версії з підтримкою TS 7 ще немає (трекінг:
typescript-eslint#10940, підтримка планується для TS >= 7.1). Відкочено на
6.0.3, бо лінт входить у гейт і щойно доданий у CI.

Обхід існує (TS 7 вміє працювати поруч із TS 6 API для eslint), але це складність
без виграшу — краще дочекатись релізу.

Обидва великі файли реально віддаються клієнту: `nova-logo.tsx:15` і
`auth-layout.tsx:29`. Логотип завантажується на кожній сторінці застосунку.

### Токен Supabase у плейнтексті

`.mcp.json` містить особистий токен доступу `sbp_…` — повний доступ до акаунта
Supabase, не до одного проєкту. Файл у `.gitignore`, в історії git **ніколи не
був** (перевірено `git log --all -S`). Ризику через репо немає; ризик локальний.

### `xlsx` — уразливість без виправлення

`npm audit` показує high: prototype pollution + ReDoS у SheetJS, `no fix
available` (пакет на npm заморожений на 0.18.5). **Вже враховано в коді:**
`generate-report.ts:11` містить коментар із номерами CVE, імпорт динамічний, і
використовуються лише API запису (`book_new`, `aoa_to_sheet`, `writeFile`).
Ненадійні файли через xlsx не парсяться — CSV-імпорт іде через papaparse.
Експозиція близька до нуля.

### `recalculate_employee_balance` суперечить моделі списання

Перебудовує баланс із графіка нарахувань і рахує лише погоджені заявки з
`start_date <= as_of`, тоді як усі шляхи погодження списують одразу. Викликається
лише в одноразових бекфілах, не в `apply_accruals`, тож зараз нічого не ламає.
Задокументовано в CLAUDE.md як пастку.

### 23 виклики `waitForLoadState("networkidle")` в e2e

Playwright не радить цей API. Не флейк сам по собі й не входив у погоджений
обсяг — лишено. Заміна на web-first асерти зробила б специфікації ще стійкішими.
